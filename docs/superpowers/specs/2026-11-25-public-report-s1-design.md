# RepoTest 公网化与第一阶段报告设计

模式：Full；沟通方式：连续执行。PUBLIC-1：本机及远端Linux/Windows CI均通过，PR #1已创建；PUBLIC-2：本地验收通过。公网监听保持关闭。
基线：10a0bc5；分支：feat/public-report-s1。需求依据为用户提供的7页公网化清单；用户已要求按清单执行，并确认起步并发1。
待补事实：域名、专用机/云厂商/预算、验证码供应商凭据；不阻塞报告层，分别在后续权限和沙箱阶段使用。当前实际实例仍是旧预览服务，观察证据不能作为新公网版本的执行或开放验收。

## 目标与阶段边界

完整目标：陌生访客预览公开GitHub URL/ref，确认精确commit并提交，得到可分享的结构化报告；只有创建者持私有令牌可取消/删除。第6节沙箱评审与第7节上线门槛全部通过前，不对公网开放。

- PUBLIC-1 报告：用例事件、包级覆盖率、失败定位、完整性说明与诊断。出口为至少20份真实go test -json输出黄金回归，以及10个固定commit真实仓库的报告验证；失败/异常时须有用例与仓库内文件行号，无终态须incomplete。不得用手写JSON冒充真实输出或用改过的源码冒充原commit失败。
- PUBLIC-2 分享：匿名只读/r/<id>，无写操作，ID高熵；摘要/失败区/过滤排序/CSP/OpenGraph/过期说明。未启用公网监听的接口验证与实际公网开放分别记录。
- PUBLIC-3 权限：公开预览/确认，人机验证，公开ID与32字节私有控制令牌分离、只存哈希；移除LAN配对与本机身份依赖。AUD-001/003必须纳入执行身份与回收/删除语义验证。
- PUBLIC-4 保护：IP每小时10/每天30，运行1加排队2，全站排队20/并发1；事务内准入/去重，任务总时长300秒、包测试120秒，过载暂停出队、元数据缓存。AUD-002/007必须关闭，IP哈希盐/留存、数据库/控制面/报告存储预算及任务readiness可检查。
- PUBLIC-5 沙箱：专用机器、无其他服务/敏感数据，验证gVisor或rootless；重跑清单对抗、资源、网络、凭据、跨任务、取消和恢复测试。两方案均不可行则保留内网。允许执行必要的固定非秘密环境配置；清单的“凭据不可见”门槛禁止API私有凭据与密钥进入容器，不解释为取消既有GOTOOLCHAIN/GOVCS等安全配置。
- PUBLIC-6 运维开放：TLS/仅80和443、维护/封禁/告警、主机重启、举报下架/30天来源记录、备份恢复/告警演练、厂商条款及所有门槛。匿名投稿不意味着多租户资源边界已经验证。

旧单管理员架构可作为内网基础，不为公网改造引入无必要的账号、Redis或新语言。保留源代码取得与离线阶段分隔；不因报告功能取消沙箱保护。

## 第一阶段接口与数据

沿用domain.Report和Package，新增兼容的可选字段：报告repo_url/commit及summary；Package.tests；用例包含name、parent、status、elapsed_ms、output、output_truncated、可选failure_location。位置字段为仓库相对path、line和可选固定commit GitHub链接。包级coverage_pct沿用已有指针；无测试/无语句覆盖信息用null，不写0%总覆盖率。

用例按Package+完整Test名字归并，按/表达父子。run/pause/cont不代表结束；pass/fail/skip是终态，没有终态保持incomplete。乱序不得由package pass把未结束用例改成passed。叶子失败优先，摘要明确统计叶子用例，包级构建失败独立展示。原包级状态/耗时保留。

输出来自不可信代码。保持现有原始日志2MiB边界，增加每用例16KiB、包诊断32KiB、报告合计输出512KiB、最多4096用例和8MiB序列化报告边界。任何限制命中都明确标记报告/输出不完整；不把被丢弃用例算作通过。报告层先解析有界实际输出，不以无限流聚合换取完整性。

覆盖率只取包级Go工具摘要；测试用例输出内类似coverage文本不能覆盖包级值。NoTests包的coverage为空。测试命令增加-cover。PUBLIC-4再把整体deadline改为300秒，此阶段不混改队列/执行权限。

失败定位优先断言输出中的.go:line；panic选第一个能映射到仓库实际文件的栈帧。DockerExecutor可提供从已校验source读取的module路径与Go文件索引，均限在仓库根内；容器/work/src前缀转换为相对路径，绝对宿主/标准库/依赖缓存路径不作为GitHub定位。模块path不同于GitHub路径、/v2、子包、恶意路径/URL要覆盖。无法确认映射时显示安全诊断，不猜一个链接。

依赖准备失败保留已有受限stderr及截断信息；诊断持久化不再返回空result。完整错误分类、重试、执行配置和资源清理P1在PUBLIC-3/4验收，当前不得宣称已修复。

本机报告页用DOM textContent渲染用例/输出/位置，不以未经转义的数据拼innerHTML。提供摘要、失败区默认展开、包过滤/排序、子用例展开、截断/缺终态提示与实际运行限制。复用页面布局；为PUBLIC-2复用可独立的报告renderer。现有LAN日志读取为内联handler，先提取为API.log复用存储读取，新增受保护本机GET /api/v1/tasks/{id}/log，仅管理员入口可读；PUBLIC-2分享不开放完整日志，PUBLIC-3改为私有能力令牌。

## 验收冻结

- PR-AC-01：真实JSON事件正确生成测试/子测试/包终态；断言失败有输出/位置，panic/构建失败可诊断，乱序/并行/强杀/非JSON行不产生假通过。
- PR-AC-02：真实-cover输出得到正确包级百分比；NoTests/null/0%区分，页面不计算未声明算法的总覆盖率。
- PR-AC-03：仅仓库实际文件能生成固定owner/repo/commit链接；跨目录、绝对宿主、标准库、恶意HTML/URL文本不泄漏或形成可执行内容。
- PR-AC-04：依赖失败日志保留，原始/用例/报告边界均有实际检查，达到边界明确truncated/incomplete。
- PR-AC-05：管理员能看到失败详情和受限日志；外源/非本机不能读取新日志入口；页面实际交互/布局/注入测试通过。
- PR-AC-06：不少于20份真正由Go工具产生的输出与至少10个固定commit真实仓库报告；记录来源、命令、Go版本、是否故障注入、exit、预期与实际。有注入的输出明确标注，不声称原仓库原commit失败。缺真实仓库验证不得把PUBLIC-1标通过或进入PUBLIC-2。
- smoke：现有runner/control/domain/cmd测试、go vet/build/gofmt；涉及容器命令的变更在现有受控验证目标验证，不修改实际正在观察的服务或开放端口。

## 实施选择与回退

采用现有Go解析器+原页面的最小扩展；新建报告服务或更换前端框架没有收益依据，暂不采用。新增字段兼容旧报告，测试先于实现。包/用例输出边界是当前上限；大量用例或截断频繁时再引入有界流式聚合，不降低公开内容安全或缺终态标准。

源码只在功能分支改造。旧运行实例与其观察计时保留为旧版本证据；新版本不得借用其被动health窗口作为公网验收。回退取回基线文件/分支，不自动改运行目标、删除数据或开放公网。
