# RepoTest 进度复核与验收缺口修复

来源：用户明确要求旧任务不可续接时重新审查进度并继续完善后续阶段。沿用现有 R-001–009、AC-001–009 和连续执行授权；本文件不新增发布范围或降低验收基线。

## 审查结论与范围

S1/S2 及 S3/S4 的接口、存储、隔离历史证据保留。S3 的 AC-002/003/004/005 用户流程仍有缺口：LAN 首页 404，会话撤销没有管理入口，活动任务删除未在浏览器暴露。S5 缺少完整安装命令，CI shell 检查只覆盖第一个文件，目标入口缺少 S5 聚焦检查。

本轮在现有可写续接副本修复这些缺口。原 F:/repotext 仍只读；已审核的旧修复 ZIP 保持不变，新修复使用独立阶段快照与合并包。

## 方案与替代

优先复用现有 API、SQLite 会话哈希、loopbackOnly、嵌入式页面、Go 测试及 shell 脚本。不引入账号体系、前端构建链或新的服务。只改文档会留下可用性缺陷；重构前端或新建账户系统超出已有单用户方案，因此采用补齐现有流程的最小方案。

LAN 的 GET / 提供同源配对与按任务 ID 读取状态/报告/日志；没有本机 CSRF token 或管理按钮。所有 API 读取仍验证现有只读 session，任务 mutation 保持 405；未知路径 404；Host allowlist 不变。页面使用现有字体、色彩和控件，表单有明确标签、加载/错误反馈，输出作为文本转义。

本机 GET /api/v1/sessions 和 DELETE /api/v1/sessions/{id} 复用 loopback 来源、Host/Origin 及随机 CSRF 校验。返回活动会话的 SHA-256 标识与过期时间，不能作为 bearer token 使用；从不返回原始 cookie。撤销写入现有 revoked 字段，旧 cookie 的任务/报告/日志读取立即失败；管理 UI 刷新会话列表并逐个撤销，不新建表。

本机运行任务也提供删除按钮，继续调用现有等退出/回收后删除的 API。视图版本号与轮询计时器使删除、换任务和旧报告响应不能相互覆盖；失败后仍能恢复查询。

S5 安装说明明确专用账号 home=/var/lib/repotest、repotest 属主与 0700，构建并安装服务和备份两个 binary，安装 env/unit 并 daemon-reload。默认 runner/LAN 关闭，实际安装和启动继续要求单独授权。CI 逐脚本运行 sh -n；新增聚焦 S5 验证入口检查临时私有 fixture、失败分支、备份与真实 health HTTP。主 Linux 入口接入该检查，传输清单涵盖脚本和部署文件并在目标展开后核对哈希。

## 验证与退出标准

- AC-002/003：LAN 首页可读，配对后按 ID 读取任务/报告/日志；未配对及撤销后 401；LAN 任务和会话 mutation 405；无本机 CSRF 泄露；页面交互实际验证。
- AC-004：本机管理列出活动会话并撤销指定会话，另一个仍有效；错误 CSRF、LAN RemoteAddr、Host/Origin、非法 ID 拒绝；不泄露 cookie。
- AC-005：运行中删除按钮调用现有 DELETE；删除后旧轮询/报告不覆盖结果，失败可继续操作。底层 Linux 资源回收仍使用既有测试并要求目标复验。
- AC-009：CI 逐脚本检查能够拒绝第二个错误脚本；S5 入口在临时路径运行，不安装服务、不替换实际数据库；部署说明经独立复核。Windows 全套 test/vet/build、格式、shell、health 通过。
- smoke：现有全套 Go 回归，LAN 来源/会话/mutation 检查，新用户流程和 S5 脚本检查。目标 Linux 新修复、原目录合并、systemd 实装、目标恢复和 7 天观察仍单独记录，不以 Windows 或静态复核代替。

## 风险、简化和恢复

单机 SQLite/现有轮询和按 ID 查报告符合首版范围；没有跨设备任务列表和账户命名需求时不引入新表。若需要多人提交或身份展示，另行设计身份模型。会话标识只是管理句柄，授权依赖本机来源和 CSRF。

阶段前 87 文件 SHA-256 与 .snapshot 恢复副本位于 work/progress-repair-20261123/before 和 baseline.json，不被 Go 或打包入口发现。回退本轮按该副本逐文件还原并移除本轮新增文件；原目录未改。不创建 Git commit、不部署、不改 SSH/provider。
