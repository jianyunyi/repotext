# RepoTest 修订方案与威胁边界

状态：实施基线 v0.1（本地开发阶段）  
依据：`RepoTest 周期设计文档（修订版）.pdf`。PDF 内的流程和技术选择作为待审查设计输入；本文件是开发执行依据。

## 1. 审查结论

原设计目标可行，但“rootless Docker + seccomp + 断网”仍共享宿主 Linux 内核，不能据此承诺可以安全地对公网运行任意陌生代码。上线门槛应表述为风险降低和经过目标环境验证，而不是证明不会逃逸。V1 公网执行应采用独立、可销毁的专用主机；若无法证明运行时和资源隔离有效，则仅提供本地/受控演示，不开放陌生用户提交。

## 2. 修订决策

1. **先做本地可验证垂直切片。** Go 模块、纯 Go、公开仓库输入；实现 URL/ref 规范化、状态机、报告模型、进程执行适配器和 HTTP 控制面。执行后端默认禁用；仅显式开启本地开发模式时执行，且不宣称这是安全沙箱。
2. **把仓库获取与代码执行拆开。** 拉取端只接受规范化 GitHub URL，禁用凭据、子模块、Git hooks、重定向和任意 refspec；校验解析到的 commit。下载体积以流式硬上限控制，不能只信 GitHub 元数据。解包后拒绝越界符号链接、设备文件、特殊文件及路径穿越。
3. **明确恶意代码边界。** 任意 Go 测试代码等同任意本地程序；进程执行器仅用于开发者自己的样例仓库。公网服务要求独立专用主机、无敏感数据/凭据、无宿主挂载、强制断网阶段、运行时硬配额及人工核验；容器配置不是虚拟机安全边界。
4. **执行器不拼 shell 命令。** 使用固定可执行文件和参数数组，固定工作目录及最小环境；拒绝用户自定义命令。进程组整体终止，超时与取消通过同一个任务终态 CAS 收敛。
5. **任务状态以持久化数据库为唯一真相。** Redis 队列仅作唤醒提示；由数据库 outbox 或可恢复扫描避免“写库成功、入队失败”。迁移先采用 SQLite 本地开发，模型保持可迁移；生产数据库后续再定。租约使用 fencing token/递增 attempt，旧 worker 不能覆盖新 attempt 的结果。
6. **去重需并发正确。** 输入 ref 先解析到完整 commit；唯一键 `(repo, commit, runner_version, config_digest)`。结果复用仅适用于成功/明确可复用终态且报告未过期。提交并发由唯一约束兜底，不能依赖先查再插。
7. **取消凭证由服务端签发。** 高熵随机 bearer token 仅在创建响应返回，数据库仅存哈希；取消需常量时间比较。分享报告 ID 与取消凭证分离。取消与完成通过条件更新决定唯一胜者，终止进程后才确认 cancelled。
8. **阶段 A 代理是独立安全组件。** 沙箱不能自行 DNS/直连；代理解析并校验每个目标 IP，拒绝 loopback、私网、链路本地、云元数据地址，防 DNS rebinding 和重定向绕过。固定 GOPROXY/GOSUMDB 等环境并验证代理 sumdb 支持；任一配置不满足则拒绝执行，不降级 direct。
9. **限制按字节/时间/资源硬执行。** 克隆数据、日志、工作目录、临时目录分别有硬上限；stdout/stderr 有界流式读取。CPU、内存、PID、磁盘配额和总超时必须验证在目标内核/运行时实际生效，否则该目标不具备执行资格。超限归因需以运行时事件为准，不能猜测 OOM/磁盘错误。
10. **报告内容均不可信。** 测试名、路径、日志、错误均需长度限制、UTF-8 修复、HTML 转义；日志按字节限额且标记截断。SSE 事件 ID 持久化或明确仅 best-effort，不能声称 Redis 丢失仍可续传。
11. **覆盖率语义修正。** `go test -cover` 的包级覆盖率不等同跨包总覆盖率；失败包可能没有完整覆盖率。无测试、构建失败、CGO 跳过和环境依赖失败分别建模，不能将“无测试”伪装为普通测试通过。
12. **隐私与滥用修正。** IP 哈希仍可能是可关联个人数据；明确盐轮换/保留期、访问控制和删除策略。报告链接视为公开 bearer URL，不放秘密；提供撤销/删除机制。验证码和 IP 限流只作为纵深防御。

## 3. 威胁边界

### 保护资产
宿主机与云元数据、运行时 socket、API/数据库/代理凭据、其他任务数据、平台可用性与带宽、用户报告完整性、提交者隐私。

### 攻击者能力
攻击者可控制仓库内容、分支/tag/commit、Go 模块元数据、测试代码、输出内容，并可并发提交恶意任务；可利用编译器/测试工具链漏洞、耗尽资源、尝试网络探测、路径穿越、符号链接逃逸、日志/XSS 注入及内核/容器漏洞。

### 主要信任边界
浏览器 → API；API → 持久化存储；worker → 容器运行时；GitHub/模块代理 → 获取阶段；获取阶段 → 离线测试阶段；单任务 → 宿主和其他任务；原始日志 → 报告渲染。

### 不在当前实现承诺内
不保证消除 Linux 内核/容器运行时零日；不防云账户/宿主管理员失陷；不保证任意上游公共代理可用或无恶意；不承诺外部服务依赖测试通过；不将本地进程模式视为沙箱；未经目标机验证不声明 CPU、内存、PID、磁盘配额有效。

### 上线阻断条件
任何凭据可见于任务；可绕过网络代理；阶段 B 可联网；资源限制无法实测；任务间可读写共享可变数据；worker 可被不可信调用方控制容器参数；恢复流程可能遗留运行中容器；安全对抗测试未通过。命中任一项禁止公网执行。

## 4. 本地首期交付顺序

A. 领域模型与状态转移、错误分类、结构化报告。  
B. URL/ref 校验及安全执行适配器接口；本地执行显式 opt-in。  
C. 控制面 HTTP API：提交、状态、报告、取消、健康检查；先用内存/SQLite实现并标注开发限制。  
D. 固定命令执行与 go test JSON 解析；日志限额、超时、取消。  
E. 容器后端仅在 Linux 目标环境验证后接入；先验证运行时参数和真实 cgroup 限额，再讨论部署。

## 5. 首期安全验收

- URL 拒绝非 HTTPS、非 github.com、userinfo、端口、IP、后缀欺骗、重定向及含控制字符输入。
- 参数经数组传递，不存在 shell 注入；ref 只允许分支/tag/完整 SHA 的有限语法。
- 超时和取消会杀死整个进程树；终态不可被迟到 worker 改写。
- 日志字节上限生效且 UTF-8/HTML 安全处理。
- 工作区路径规范化，越界链接/路径被拒绝。
- 公网执行仍须独立 Linux 主机进行隔离与资源上限验收，本地通过不替代该门槛。
