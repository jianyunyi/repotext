## 需求理解

从零开发 RepoTest。首个可交付版本是本地 Web 服务：Windows 开发、Linux 主机运行；用户通过 GitHub URL 预览公开仓库、ref 和完整 commit SHA，确认后创建任务并执行 Go 构建/测试，查看状态和报告。当前确定的阶段前置要求是：先完成真实 URL 校验和仓库/commit 预览，不使用模拟任务；本轮 S2 先做页面和只读任务流程，执行器后续阶段接入。

访问边界：服务可从局域网访问查看；LAN 客户端须通过启动时打印的一次性配对码首次绑定，设备保存会话。LAN 设备只读。只有本机浏览器能提交、确认执行、取消和删除。用户主动粘贴 URL 并二次确认具体 commit 才授权执行。

数据：任务元数据、报告、受限日志保留 7 天并清理；用户可立即删除，运行中同时取消。相同仓库/commit 在 10 分钟窗口内复用结果，但键还包含 Go 版本、执行器版本、配置摘要。

范围：公开 GitHub、Go 模块、默认分支/分支/tag/40 位 SHA；Linux 是执行目标，Windows 是开发环境。目标机实测 Debian 13 x86_64，服务预览返回 linux/amd64。不做公网服务、账号系统、任意命令、私有仓库和其他语言。LAN 的读取口令不是提交授权。

约束与假设：Linux 主机已可用；主机架构、内核、容器运行时、反向代理和持久化数据库尚未现场核实。S1 只冻结架构与验收；任何本地进程执行都不作为不可信代码沙箱，容器资源隔离须在 Linux 实机实测。已有 Go 骨架来自此前阶段，未经本设计验收，不视为满足本文流程。

## 方案

### 用户流程
1. 本机用户在 `/` 粘贴 HTTPS GitHub URL，可选 ref。
2. API 严格解析 URL；不跟随重定向，不接受 userinfo、端口、非 github.com、路径穿越。服务查询 GitHub 元数据与 ref，将 ref 固定到完整 commit；克隆/归档大小必须有实际硬上限，不能只信 API 元数据。
3. 页面展示仓库名、公开状态、默认分支、输入 ref、解析 SHA、预期 GOOS/GOARCH（从实际服务运行时读取）和限制说明。此时不建执行任务、不生成模拟报告。
4. 本机用户明确确认此 commit 后才创建任务。执行器未接入时提交显示“执行能力尚未启用”，不能伪成功。
5. 任务页显示真实持久化状态/阶段/错误。报告只在真实执行后存在。LAN 配对设备只读查看。
6. 删除需本机权限；运行中删除先请求取消并等资源回收，再删任务数据。后台 7 天 TTL 清理兜底。

### 信任与安全边界

可访问性是两层独立策略：用户确认的“LAN 只读”适用于所有已配对 LAN 设备，无需逐设备 allowlist；启动配对码由 operator 手动交付。写操作只由运行服务的本机管理员使用。另设的“公网未认证访问”当前禁止，对公网暴露时必须关闭服务或另行经过威胁评审。当前尚未批准、会改变产品行为的政策只有公网暴露，而不是 LAN 设备逐台准入。

服务使用两个显式绑定地址，LAN listener 仅提供配对和读取路由；本机 loopback listener 提供管理操作。两个 listener 均要求合法 Host、严格 CORS 禁止跨源、SameSite cookie、CSRF token 和 Origin 校验。配对本身无需先有会话，但只签发只读会话，带速率限制；配对码从终端读取。启动后先以只读安全模式运行，SQLite 启动迁移成功且 listener 策略校验通过后才开放 API；迁移失败则拒绝启动。API 与 UI 共享同源，production 阻止任意跨源调用。
攻击者控制仓库文件、go.mod、测试代码和所有输出；可恶意构造 URL/ref、依赖、压缩包、日志、资源消耗和并发请求。资产包括宿主机、其他任务、运行时 socket、凭据、局域网其他服务和本地报告。

本机 UI 原点是副作用授权边界，不能只信 Host/Origin 字符串：绑定 loopback listener/本机单独入口，以随机 CSRF token、SameSite cookie、Origin/Host 校验和 DNS rebinding 防护组合实现。LAN listener 的路由/方法白名单仅允许绑定后读取；所有状态变更在服务层再次校验 capability，而非只在 UI 隐藏按钮。

配对流程：启动生成一次性高熵码，仅写服务端终端；限时、限次、首次成功即失效；不能经 LAN API 读取。交换成每设备随机会话 token，服务端仅存哈希，Secure/HttpOnly/SameSite cookie，支持撤销与轮换。配对只能授予 LAN 只读能力。日志和报告文本不可信，统一转义，不使用 HTML 注入。

公网/陌生人提交不在本项目授权范围。LAN 读取不代表 LAN 执行授权。执行器接入前不执行任何仓库代码。执行阶段分隔：获取依赖阶段仅经 DNS/IP 校验代理出站；测试阶段断网。容器共享宿主内核，不能视作绝对隔离；目标机隔离验收不通过则执行器保持关闭。

### 技术方案（待 S2 开始前按实际主机核对）
- Go 控制面服务；优先单二进制嵌入静态页面，减少 Node 运行时与反向代理依赖。S2 先由标准库 HTTP 服务托管页面/API；默认 loopback 绑定。S3 配对只读认证完成前拒绝 LAN bind。
- SQLite WAL 保存任务、预览、报告元数据、设备会话哈希、审计事件；事务 outbox/可恢复扫描驱动队列。若 Linux 并发或可靠性实测不满足再迁移 MySQL，不预先引入 Redis。
- SSE 或轮询先择简单实现；任务状态以持久化库为真相，事件断线后 GET 状态可恢复。
- GitHub metadata 使用无凭据公开接口，未配置令牌时遵守未认证限流；不得把 token 注入执行容器。
- API 对象能力：预览 ID 与任务 ID 不作秘密。LAN read session 与本机 mutation capability 分开；LAN 不可调用写路由。
- 结果复用唯一键：规范 repo、完整 SHA、Go 版本、runner 镜像/版本、配置摘要；只复用真实终态结果，10 分钟从完成时起算。

### 失败与恢复
非法 URL/ref、私有仓库、过大仓库在确认前拒绝；GitHub 限流显示可重试时间；配对码过期/重放拒绝；任务持久化成功但调度失败由 outbox 扫描恢复；重复请求由数据库唯一约束处理；LAN 客户端断线后重新读取当前状态；清理器幂等重试；取消与完成竞争由单次条件状态转移裁决，旧 worker 用 fencing token 不能覆盖新结果。

## 历史 · 2026-11-18 · S3 实现级设计补充

以下记录当时尚未接入 CSRF、worker/outbox 和活动删除的设计状态，保留作为历史，不表示当前缺陷。当前实现和证据以本文顶部及 2026-11-23 进度复核节、stage-report.md 的最新条目为准。

### 组件边界
- 两个 listener：loopback 管理 listener 提供本机预览与所有变更；LAN listener 只挂载配对、健康检查和 GET 任务/报告路由。LAN handler 采用显式路由 allowlist，未知路径与所有写方法拒绝。
- 配对码由加密安全随机数生成，只打印终端；5 分钟有效、限 5 次失败、首次成功即消费。绑定会话使用至少 256-bit 随机 token，数据库仅存 SHA-256 哈希，cookie HttpOnly、SameSite=Strict、Path=/。配对会话只读，可撤销，默认 30 天过期。
- 本机变更路由仅由 loopback listener 暴露，并校验 Host=localhost/127.0.0.1、Origin 与 CSRF token；LAN listener 不接受任何 mutation，即使携带本机 cookie。
- SQLite 为真相存储，使用 WAL、外键和事务；数据库文件权限 0600。表包括 tasks、reports、logs、sessions、pairing_state；任务状态采用条件更新。
- TTL 清理器每小时批量删除 7 天前终态任务及子表；运行中的任务不做数据级联，先取消/回收再删除。手动删除仅本机可用。
- 本阶段执行器关闭，提交/确认执行返回 runner_disabled；不会造任务或模拟报告。为后续阶段保留持久化 task schema 与删除/取消接口。

### S3 验收
- AC-002：未配对 LAN 读取拒绝；配对后任务/报告/日志读取可用；LAN mutation 拒绝；loopback mutation 成功；Host/Origin 伪造拒绝。CSRF token 尚未实现，AC-002 暂不通过。
- AC-004：配对码仅终端出现；正确码首次绑定成功；过期、猜测限额、重放失败；会话 token 数据库只存哈希，撤销后立即失效。
- AC-005：到期任务、报告、日志按批次和外键清理；手动删除终态任务后数据不可再读；执行器尚未接入，活动任务返回 409，不能声称运行中取消与进程回收已通过。
- AC-007：SQLite 重启后任务状态一致；事务内状态转移；重复创建使用唯一约束；缓存键含 repo/SHA/Go/runner/config。
- migration 失败时进程不得开放任何 listener；数据库文件与会话不能由其他 OS 用户读取。

- 本轮实际实现：本机删除仅允许终态任务；loopback bind/Host 使用显式 loopback IP；listener 全部绑定成功后才开放服务。活动态删除回收、CSRF token 与 outbox/cache key 保留为未关闭验收项。

### 风险与降级
认证或 listener 分流验收失败时禁用 LAN listener，loopback 单机模式仍可用。SQLite 文件损坏时停止服务并保留原文件供人工恢复，不自动重置数据库。配对码输出不可写或终端不可用时，LAN listener 不启动。
